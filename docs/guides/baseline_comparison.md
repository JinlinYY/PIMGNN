# Baseline Comparison Protocol

## What the comparison represents

The numerical baseline values distributed with PSMI were generated by running
baseline implementations on the PSMI data protocol. They were not copied from
the papers that introduced or previously used the model families. The cited
literature provides methodological provenance; the values in the comparison
table come from the repository's common split, targets, metric implementation,
and multi-seed runs.

This distinction is essential when interpreting Table 1: a number from an
external publication would usually use a different dataset, split, target, and
aggregation and would not be a controlled comparison with PSMI.

## Shared data protocol

The common five-seed runner reconstructs the benchmark from:

```text
datasets/processed/update-LLE-all-with-smiles.xlsx
datasets/splits/main_benchmark_system_split.json
```

It applies the six-record density filter, assigns systems from the fixed JSON
manifest, and augments only the training partition. The runner records both
input paths and SHA-256 digests in its output `protocol.json`.

The equivalent prepared tables under the following directory are an audit and
interoperability export, not the direct input of the common runner:

```text
datasets/processed/baseline_comparison/
|- train.csv
|- validation.csv
|- test.csv
|- total.csv
`- split_manifest.csv
```

These files are exported from the same filtered workbook and fixed system-level
manifest. The preparation script checks that train, validation, and test system
identifiers do not overlap. Method-specific wrappers that require CSV input can
use these tables after their schema expectations have been verified.

Inspect the export interface with:

```bash
python scripts/data_preparation/prepare_baseline_comparison_data.py --help
```

Use `--out-dir` to create a new export without overwriting the distributed
tables. Do not create a new random row split when claiming the distributed
comparison.

## Inputs and targets

Every baseline predicts the same ordered six-component target:

```text
[Ex1, Ex2, Ex3, Rx1, Rx2, Rx3]
```

The input representation depends on the model family, while temperature and
phase-path information are supplied according to the baseline implementation:

| Family | Molecular representation |
| --- | --- |
| MLP / ANN / LSTM / Transformer / TabKNet | Three component fingerprints with model-specific fusion |
| Random forest / XGBoost / TabNet | Tabular fingerprint and condition features |
| SMILES RNN | Concatenated tokenized component SMILES plus condition scalars |
| GNN | Three molecular graphs plus normalized temperature and phase path |
| CIGNN / CGIB / GLAM / MMGNN | Method-specific graph interfaces in `src/psmi_baselines/` |

Representations are intentionally model-specific, but the source records,
partition assignment, target order, and aggregate metric definitions must remain
fixed.

## Training and model selection

For each seed and model:

1. training uses only the training table;
2. normalization and learned preprocessing are fitted from training data;
3. checkpoint or hyperparameter selection uses validation performance;
4. the fixed test table is evaluated after selection;
5. overall and phase-specific MAE, RMSE, and R2 are exported;
6. per-seed results are aggregated as mean and sample standard deviation.

The common five-seed runner uses:

```text
42, 123, 456, 789, 2024
```

These seeds differ from the maintained PSMI three-seed summary. Do not combine
the two standard deviations or describe them as the same replication protocol.

## Common baseline commands

Inspect the complete interface:

```bash
python scripts/experiments/baselines/run_classical_multi_seed.py --help
```

A core-environment run excludes the two implementations with additional
runtime dependencies:

```bash
python scripts/experiments/baselines/run_classical_multi_seed.py \
  --models ann gnn lstm mlp random_forest smiles_rnn tabknet transformer \
  --seeds 42,123,456,789,2024 \
  --out-dir outputs/baseline_comparison/core_five_seed \
  --device cuda
```

The common GNN baseline uses the repository's native PyTorch dense-adjacency
implementation and does not require PyTorch Geometric. The complete ten-model
comparison additionally requires `xgboost` and `pytorch-tabnet`. After
installing and import-checking those optional dependencies, run:

```bash
python scripts/experiments/baselines/run_classical_multi_seed.py \
  --models ann lstm mlp random_forest smiles_rnn tabknet tabnet transformer xgboost gnn \
  --seeds 42,123,456,789,2024 \
  --out-dir outputs/baseline_comparison/complete_five_seed \
  --device cuda
```

`--quick` runs only seeds 42 and 123 and is for interface checking, not
reproduction of the five-seed table. The optional package installation is
documented in [Installation](../getting_started/installation.md).

## Graph and specialized entry points

Method-specific wrappers are available under
`scripts/experiments/baselines/`, including:

- `run_cignn.py` and `evaluate_cignn.py`;
- `run_cgib.py` and `evaluate_cgib.py`;
- `run_glam.py` and `evaluate_glam.py`;
- `run_mmgnn.py`;
- `run_solvbert.py` and `predict_solvbert.py`;
- BigSolDB training, prediction, and metric recomputation wrappers.

Some graph baselines require `torch_geometric` in addition to the core PSMI
environment. Some external-transfer baselines require separately licensed data
or pretrained artifacts. Read the wrapper and its method-specific source before
running it.

## Archived reference outputs

The public five-seed evidence is located at:

```text
experiments/section_3_results/3_1_lle_prediction/
  3_1_1_baseline_comparison/results/reference_five_seed/
```

Key files are:

- `all_models_overall.csv`: one overall MAE/RMSE/R2 row per model;
- `fingerprint_and_sequence_models/multiple_seeds_metrics_detail.csv`:
  per-seed detailed records;
- `fingerprint_and_sequence_models/multiple_seeds_summary.csv`:
  long-form mean and standard deviation;
- `fingerprint_and_sequence_models/multiple_seeds_summary_formatted.csv`:
  paper-friendly phase and overall columns;
- `gnn_extension/`: graph-extension details and summary.

The combined archived overview contains ten model labels: ANN, LSTM, MLP,
random forest, SMILES RNN, TabKNet, TabNet, Transformer, XGBoost, and GNN.

## Metric aggregation

Overall metrics flatten the six outputs over all test rows. Phase-specific
metrics use the first or last three outputs. The same definitions are described
in [Evaluation Metrics](../results/evaluation_metrics.md).

When comparing with a value reported by another repository, align:

- exact test systems and records;
- target normalization and output ordering;
- molecular representation and condition features;
- model-selection criterion;
- number and identity of seeds;
- pointwise versus system-averaged aggregation.

## Fairness boundaries

A controlled baseline comparison does not require every model to have the same
architecture or molecular representation. It does require that information
access and evaluation protocol be comparable. In particular:

- no model may train on validation or test labels;
- test systems remain chemically disjoint from training systems;
- augmentation, if used, is restricted to training data;
- preprocessing statistics come from training data;
- all models predict the same six mole fractions;
- all rows use the same metric code and test table.

Model-specific pretrained representations or external data must be disclosed as
additional information access.

## Reproducing versus citing

When describing the table, state both sources of provenance:

1. cite the original publication for each model family or methodological idea;
2. cite the PSMI repository and state that the reported numbers were obtained
   by the provided implementations on the shared PSMI benchmark protocol.

Do not imply that the original cited articles contain the exact PSMI table
values.

## Sanity checks before reporting a rerun

1. Verify the split manifest and row counts.
2. Confirm all selected seeds completed; do not treat a missing seed as zero.
3. Inspect per-seed files before the aggregate summary.
4. Confirm identical test-table hashes across models.
5. Confirm overall metrics use all six outputs.
6. Record package versions and optional pretrained artifacts.
7. Keep rerun outputs separate from the archived reference directory.
